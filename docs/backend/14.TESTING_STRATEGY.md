# Backend Testing & Quality Assurance Strategy

## 1. Testing Philosophy
The Manohar Grand backend requires high-assurance testing around financial transactions, date math, inventory double-booking prevention, and authorization boundaries.

```
       ▲
      / \     End-to-End & Concurrency Tests (10%)
     /   \    API Contract & Integration Tests (30%)
    /_____\   Unit Tests (Date Math, Pricing, Models) (60%)
```

---

## 2. Test Execution Tiers

### 2.1 Tier 1: Unit Tests (`pytest-django` / `django.test.TestCase`)
- **Inventory & Night Math**:
  - Validates check-in/check-out night intervals across month/year boundaries and leap years.
  - Tests 0-night edge cases (check-in == check-out) and inverted date validation.
- **Authoritative Pricing Engine**:
  - Tests base rate + extra adults (3rd/4th guest) + GST slabs (0%, 12%, 18%) + misc service charges.
  - Verifies calculation precision using Python `Decimal` (zero floating point drift).
  - Tests immutable price snapshot creation upon booking confirmation.
- **Cancellation Policy Calculator**:
  - Tests exact 48-hour cutoff boundary (e.g., 48.1 hours vs 47.9 hours).
  - Verifies 50% refund calculation for cancellations $\ge 48\text{ hrs}$ and 0% for same-day cancellations.

### 2.2 Tier 2: API Contract & Integration Tests (`APITestCase` / `APIClient`)
- **Phase 1 Authentication & Security Test Suite**:
  - **Google OAuth Tests (Mocked)**:
    - Successful first-time customer registration (creates `User`, `SocialAccount`, `CustomerProfile`).
    - Returning Google customer login (finds existing user, sets session).
    - Automatic account linking when email matches an existing account (`SOCIALACCOUNT_EMAIL_AUTHENTICATION_AUTO_CONNECT`).
    - User cancelled OAuth consent / access denied handling.
    - OAuth error responses from provider.
    - Invalid or expired OAuth state parameter (CSRF state validation).
    - Upstream token exchange failure handling.
  - **Session & CSRF Lifecycle Tests**:
    - `GET /api/v1/auth/csrf/` setting `csrftoken` cookie and returning token.
    - `GET /api/v1/auth/me/` returning HTTP 401 for unauthenticated requests.
    - `GET /api/v1/auth/me/` returning authenticated customer profile for active sessions.
    - `POST /api/v1/auth/logout/` invalidating session and clearing cookies.
    - Protected endpoints returning HTTP 401 after logout.
  - **Staff & RBAC Credentials Tests**:
    - Successful email/password staff login setting session cookie.
    - Invalid password handling (HTTP 401 and failed attempt logging).
    - Inactive staff account denial (`is_active=False`).
    - Role-based permission enforcement (e.g. Receptionist denied Manager endpoints).
    - Valid role access validation for `SUPER_ADMIN`, `MANAGER`, `RECEPTIONIST`.
- **Booking Hold & State Transition Workflow**:
  - Hold initiation $\to$ Payment verification $\to$ Confirmation.
  - Hold expiration $\to$ Automated inventory release $\to$ Re-availability verification.
- **Razorpay Payment Integration (Mocked)**:
  - Mocked Razorpay client order generation.
  - Correct HMAC-SHA256 signature verification vs fraudulent signature rejection (400 Bad Request).
  - Idempotent webhook delivery simulation (repeated events handled gracefully without double-crediting).

### 2.3 Tier 3: Concurrency & Double-Booking Stress Tests
- **Simultaneous Hold Collision Simulation**:
  - Simulates 10 concurrent customer requests attempting to reserve the last remaining room (out of 20 AC rooms) for the same date range.
  - Asserts that exactly 1 request succeeds (HTTP 201) and 9 requests receive HTTP 409 Conflict.
- **PostgreSQL Transaction Isolation Testing**:
  - Validates `select_for_update()` locking semantics in staging environments.

## 3. Test Fixtures & Seed Data

### 3.1 Standard Test Baseline
- **Physical Rooms Setup**:
  - 20 AC rooms (`AC-101` to `AC-120`).
  - 8 Non-AC rooms (`NAC-201` to `NAC-208`).
- **Standard Rate Plans**:
  - Base AC Room: ₹2,500/night (`CONFIGURABLE / DEMO`).
  - Base Non-AC Room: ₹1,800/night (`CONFIGURABLE / DEMO`).
  - Extra Adult: ₹500/night (`CONFIGURABLE / DEMO`).
  - GST: 12% (`CONFIGURABLE / DEMO`).

## 4. Quality Gate & Phase Completion Protocol

Prior to marking any development phase complete, the following checklist is executed:
1. `python manage.py check` (0 errors).
2. `python manage.py makemigrations --check --dry-run` (no missing migrations).
3. `pytest --cov=. --cov-report=term-missing` ($\ge 85\%$ test coverage on core engines).
4. `flake8` / `black --check` (PEP8 code formatting).
5. Manual integration verification against frontend API client contracts.
