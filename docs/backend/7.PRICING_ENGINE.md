# Dynamic Pricing Engine & Immutable Financial Snapshot Architecture

## 1. Authoritative Calculation Pipeline

The backend is the sole authoritative calculator for reservation financial totals. The pricing engine executes the following formula in strict sequential order:

$$\text{Total Payable} = \text{Base Room Total} + \text{Extra Guest Surcharges} + \text{Taxes (via active TaxRule)} + \text{Misc Charges} - \text{Discounts}$$

```
+-----------------------------------------------------------------------------------+
|                           PRICING PIPELINE EXECUTION                              |
|                                                                                   |
|  1. BASE ROOM CHARGE:                                                             |
|     Sum( Category.base_price_per_night * Quantity * Nights )                      |
|                                                                                   |
|  2. EXTRA GUEST CHARGES (Configurable Rules):                                     |
|     For each room:                                                                |
|       Extra Adults = max(0, Allocated Adults - included_adults)                   |
|       Extra Charge = Extra Adults * extra_adult_charge * Nights                   |
|                                                                                   |
|  3. TAX CALCULATION (Dynamic TaxRule):                                            |
|     Taxable Base = Base Room Total + Extra Guest Charges (based on applicability) |
|     Tax Amount   = Taxable Base * (active_tax_rate / 100)                         |
|                                                                                   |
|  4. MISCELLANEOUS & DISCOUNT ADJUSTMENTS:                                         |
|     Total Payable = Taxable Base + Tax Amount + MiscCharges - Discounts           |
+-----------------------------------------------------------------------------------+
```

## 2. Configurable Occupancy & Extra Guest Rules

- **Client Stated Occupancy Limits**:
  - AC Room: Maximum 4 PAX. Base rate covers standard occupancy (2 adults); extra occupant charges apply for additional guests.
  - Non-AC Room: Client explicitly stated "2 PAX only" (Note: One example mentioned 3 PAX; recorded as **UNRESOLVED CLIENT QUESTION**, working baseline = 2 PAX).
  - *Admin Control*: Max occupancy limits are fixed per hotel policy and not freely editable by admins unless explicitly requested.
- **Client-Confirmed Extra Guest Fees**:
  - `extra_adult_charge`: **₹350** per night
  - `extra_child_charge`: **₹300** per night
- **Configurable Architecture**: Surcharges and base rates are stored in centralized backend pricing configuration (`RoomCategory` / `RatePlan`) rather than hardcoded in frontend components.

---

## 3. Configurable Tax & GST Architecture

- **Client-Confirmed GST Baseline**: **5% GST** is the current active rate.
- **Dynamic Calculation via `TaxRule` Model**:
  - `tax_rate`: Decimal percentage (baseline: `5.00%`).
  - `tax_applicability`: Percentage on taxable accommodation total.
  - `taxable_components`: Room tariff + Extra guest surcharges.
  - `effective_from` & `effective_to`: Optional date ranges for tax regime shifts.
  - `is_active`: Boolean toggle.
- Tax rules are centrally managed in the backend database. The backend calculates the authoritative final gross amount.

---

## 4. Late Check-Out Pricing

- **Client-Confirmed Hourly Rates**:
  - AC Room: **₹150** per hour
  - Non-AC Room: **₹100** per hour
- **Policy Window**:
  - Permitted up to 3 hours beyond standard checkout (11:00 AM to 2:00 PM).
  - Checkouts beyond 3 hours incur a full extra day charge.
- Surcharge calculations are processed server-side during checkout finalization.

---

## 5. Payment Split Architecture (50% Advance)

- **Online Direct Bookings**:
  - **Advance Due (Online via Razorpay)**: 50% of the gross total (including GST).
  - **Balance Due (At Front Desk)**: Remaining 50% payable prior to room key handover.
- The authoritative pricing engine computes `advance_amount_due` (50%) and `balance_amount_due` (50%) in the snapshot.

---

## 6. Immutable Booking Price Snapshot

### Purpose & Rationale:
Room tariffs, extra occupant charges, and tax slabs fluctuate over time. When an admin updates room rates or tax rules, past bookings and completed transactions must **never** be retroactively altered.

### Schema of `BookingPriceSnapshot`:
When a booking is confirmed, an immutable snapshot row is created:
```json
{
  "room_subtotal": "3198.00",
  "extra_guest_total": "700.00",
  "tax_rule_applied": "GST (5% Accommodation)",
  "tax_rate_percent": "5.00",
  "tax_amount": "194.90",
  "miscellaneous_charges": "0.00",
  "discount_amount": "0.00",
  "gross_total": "4092.90",
  "advance_amount_due": "2046.45",
  "balance_amount_due": "2046.45",
  "currency": "INR",
  "itemized_rooms": [
    {
      "category_id": "ac-room",
      "category_name": "AC Room",
      "quantity": 1,
      "rate_per_night": "1599.00",
      "nights": 2,
      "line_total": "3198.00",
      "included_adults": 2,
      "actual_adults": 3,
      "extra_adults": 1,
      "extra_adult_charge": "700.00"
    }
  ]
}
```
All customer invoices, payment validations, accounting ledgers, and front-desk balance collections derive exclusively from this permanent snapshot record.
