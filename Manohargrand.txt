Yes. Now that we're moving from the frontend prototype into the **real application**, I recommend we first freeze the product architecture before writing Django code.

One important update from the current ecosystem: **Django 6.0 is currently supported, while Django 5.2 is the current LTS line through April 2028**. For a hotel booking system that we want to maintain for years, I recommend **Django 5.2 LTS** rather than chasing the newest feature release. ([Django Project][1])

And for Google login, we should validate the Google ID token **on our Django backend** and create/manage our own application session; Google's documentation explicitly describes the ID-token-to-backend flow this way. ([Google for Developers][2])

For Razorpay, our eventual architecture should create the Razorpay order **server-side**, verify the returned signature on the server, and use webhooks as an important payment-status source. ([Razorpay][3])

# 17. Availability algorithm

Customer searches:

```text

Check-out
Guests
Rooms
```

Backend checks **every night**:

```text
check_in <= date < check_out
```

For each requested room category:

```text
minimum available inventory across all nights
```

Example:

```text
AC

Sep 28 → 10
Sep 29 → 8
Sep 30 → 5
```

Customer asks for:

```text
6 AC rooms
```

Result:

```text
NOT AVAILABLE
```

because the minimum availability is 5.
